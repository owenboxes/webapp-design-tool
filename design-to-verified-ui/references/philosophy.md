## 0. 한 문장
**사용자가 판단해야 할 것을 줄이되, 알아야 할 것은 숨기지 않는다.**

- 앞부분(줄이기)은 토스·GS칼텍스 에너지플러스, 뒷부분(숨기지 않기)은 카카오뱅크·토스 비판·Apple Responsibility에서 왔다.
- Apple HIG의 말처럼 **단순함은 미니멀리즘이 아니다** — 중요한 것은 가까이, 나머지는 물러나게.
- 일관성은 감각이 아니라 시스템으로 지킨다(TDS·SEED).

## 1. 화면 모드 — 이 철학의 핵심 구조

모든 화면은 둘 중 하나의 모드로 설계한다. 설계 시작 시 화면별 모드를 먼저 적는다.
**판단 기준: 이 행동을 되돌릴 수 있는가?** 되돌릴 수 있으면 기본 모드로 가볍게, 되돌릴 수 없거나 비용·위험·법적 조건이 있으면 번역 모드.
- *(v0.3-B)* **기간 안에 취소할 수 있는 행동은 "되돌릴 수 있음"으로 분류한다.** 예: 구독 해지 예약(이용 종료일 전까지 해지 취소 가능), 주문 취소 요청, 예약 변경. 이런 행동은 조건 안내는 번역 모드로 하되, 실행 후 **"○○ 예정" 상태로 남기고 취소 경로를 제공**한다.
  - *(v0.4-H)* "○○ 예정" 항목은 **목록에서도** 다른 항목과 구분해 보인다(배지·배경 톤·강조선 등). 상세 화면에 들어가지 않아도 **언제까지 취소할 수 있는지**(이용 중이면 이용 종료일도) 목록에서 읽을 수 있어야 한다.
- 진짜 되돌릴 수 없는 행동: 즉시 종료, 데이터 영구 삭제, 송금·결제 확정 등. 실행 전 확인 + "되돌릴 수 없음" 명시.
  - *(v0.5-K)* **안내의 무게는 위험에 맞춘다.** 잃는 것이 작고 비용·법적 조건이 없는 행동(최근 검색어 전체 삭제, 알림 목록 비우기 등)은 확인 질문이나 버튼 옆에 **"(복구 불가)" 같은 짧은 표기 하나**면 충분하다. 별도 설명 단락·조건 표·팝업을 늘리지 않는다. 그래도 표기 자체는 빠뜨리지 않는다. 돈·계정·사용자가 만든 콘텐츠처럼 잃는 것이 큰 행동은 기존 번역 모드 그대로.

| | 기본 모드 (Decide) | 번역 모드 (Understand) |
|---|---|---|
| 언제 | 일반 탐색·입력·선택·완료, 되돌릴 수 있는 행동 | **위험·비용·법적 조건·되돌릴 수 없는 행동** (결제, 해지, 동의, 삭제, 계약, 투자, 개인정보 제공 등) |
| 원칙 | 한 화면에 한 가지 결정. 지우고 쪼갠다 | 정보를 지우지 않는다. 쉬운 말로 풀고 순서를 잡는다 |
| 정보량 | 최소 | 필요한 만큼 전부 |
| 구조 | 큰 제목(질문형 가능) → 입력/선택 → 주요 행동 1개 | 쉬운 요약 → 핵심 조건(금액·기간·위험·취소 방법)을 **항상 보이게** → 용어 풀이 → 원문(점진적 공개 가능) → 행동 |
| 안전장치 | 실행 후 되돌리기(취소/실행 취소) 제공 | 실행 전 확인. 되돌릴 수 없음을 명시 |
| 금지 | 한 화면에 결정 여러 개 섞기 | 핵심 조건을 접기 영역 안에만 두기, 위험을 친근한 말로 축소하기(예: 미수거래 → "외상"), **사용자 상태와 맞지 않는 고정 문구** |

- *(v0.3-C)* **번역 모드의 조건 문구는 사용자의 현재 상태로 계산한다.** 같은 해지 화면이라도 결제 전·이용 중·해지 예정에 따라 "청구되는 금액", "이용 종료일", "환불 여부"가 달라진다. **틀린 안심 문구는 정보를 숨기는 것보다 나쁘다.** 상태별 문구 표를 산출물에 포함한다.

## 2. 원칙 10가지

1. **판단을 줄인다** — 기본 모드 화면은 결정 1개. 여정의 단계 수를 세고 기록한다(개선 전후).
2. **알아야 할 것은 숨기지 않는다** — 번역 모드 규칙 적용. 단순화보다 정확성이 우선. 데이터·권한 요청에는 무엇을 왜 쓰는지 밝힌다.
3. **쉬운 말로 번역한다** — 전문용어는 일상어로, 불필요한 단어는 뺀다("잡초 뽑기"). 상세 규칙은 §4.
4. **맥락에서 시작한다** — 설계 전에 사용 맥락(기기·장소·자세·시간 압박·사용자 숙련도)을 적는다. 톤도 맥락에 맞춘다(같은 목소리, 상황별 톤).
5. **기다림을 디자인한다** — 로딩·실패·재시도·빈 상태를 모든 주요 화면에 정의한다. 되돌릴 수 없는 작업은 "처리 중"과 "완료"를 구분한다.
   - *(v0.4-G)* **로딩 중의 할 일은 기다리기다.** 로딩 화면에 눈에 띄는 주요 버튼(예: "다시 시도하기")을 두지 않는다. 벗어날 길이 필요하면 보조 텍스트 버튼 하나만 두거나, 지연이 길어졌을 때만 보인다. "다시 시도"는 실패했을 때(오류 상태)의 행동이다.
6. **더하기보다 뺀다** — 새 요소는 기존 요소를 대체하거나 근거(사용 빈도·사용자 목표)가 있을 때만 추가한다.
7. **시스템으로 지킨다** — 색은 역할 토큰으로, 글자는 정해진 스타일 세트로, 상태(기본·눌림·포커스·비활성·오류)는 컴포넌트마다 정의한다. 규칙은 사람과 에이전트가 모두 읽을 수 있게 문서화한다.
8. **되돌릴 수 있게 한다** *(v0.2, Apple Agency / v0.3-A 범위 명확화)* — 실수에서 쉽게 복구(취소·실행 취소·이전 단계). 사용자를 하나의 흐름에 가두지 않는다.
   - 여러 단계 흐름의 되돌리기는 **"← 이전" + 흐름을 닫는 "닫기(또는 ○○ 취소)" 하나**로 충분하다. 선택지마다 "선택 취소" 버튼을 붙이지 않는다(다른 걸 고르면 된다).
   - "건너뛰기"는 **온보딩·튜토리얼·선택 사항 안내**에만 쓴다. 필수 입력을 추천값으로 채우는 기능은 "추천대로 채우기"처럼 무엇이 일어나는지 말하는 보조 링크로.
   - **단계 화면 하단 행동은 최대 2개**(주요 1 + 보조 1). 그 밖의 나가기는 상단(이전·닫기)에.
9. **익숙한 관례를 먼저 쓴다** *(v0.2, Apple Familiarity)* — 사람들이 이미 아는 패턴(웹 표준 컨트롤, 일반적인 위치·아이콘)을 우선. 새 패턴은 기존 관례로 해결되지 않을 때만, 이유를 기록하고 쓴다.
10. **감정은 정하되 장식하지 않는다** *(v0.2, Apple Delight)* — 제품마다 전하고 싶은 감정 1개를 정한다(예: 안심, 성취, 가벼움). 완료·축하·위로 같은 순간에 그 감정을 담되, 과업을 방해하거나 느리게 하는 장식 효과는 쓰지 않는다.

## 3. 기본값 (2026-11-10 확정)
- **문구 톤** *(v0.5-J)*: 해요체 기본. 사이트 성격(공공·금융·법률 안내, 브랜드 목소리 등)이나 사용자 요청에 따라 다른 어조(합쇼체 등)로 바꿀 수 있다. 어조는 작업 시작 때 확인하고 설계 문서에 적는다. **정한 어조는 사이트 전체에서 하나로 통일한다**(한 화면에 "없어요"와 "없습니다"가 섞이면 위반). 법적 원문·고유명사는 바꾸지 않는다.
- **시각 스타일**: 제품마다 입력받는다. 스킬은 작업 시작 시 브랜드 색·무드·참고 서비스·전하고 싶은 감정(원칙 10)을 묻는다.
  - 입력이 없을 때의 대체값: 무채색 기반 + 강조색 1개(주요 행동), 오류·삭제는 별도 역할 색. 결과물에 "대체값 사용"이라고 표시한다.
  - 어떤 스타일이든 공통 규칙: 색은 역할 토큰으로, 글자 스타일 수는 적게(위계는 굵기 대비), 한글 본문 굵기 500 이상 권장, 숫자·금액은 크고 굵게, 여백으로 그룹 구분.
- **효과보다 읽힘** *(v0.2)*: 투명·블러·그라데이션·이미지 위의 텍스트는 **접근성 설정을 켜지 않은 기본 상태에서** 대비 기준을 충족해야 한다. 유리·블러 효과는 내비게이션 레이어(상단바·탭바·시트 테두리)에만, 본문·목록·표 위에는 쓰지 않는다.
- **누를 수 있어 보이는 모양은 누를 수 있는 것에만** *(v0.3-E)*: 화살표(↗ › →), 밑줄, 알약(pill)·버튼 모양 테두리, 손가락 커서는 실제로 동작하는 요소에만 쓴다. 정보 표시용 태그는 버튼과 구분되는 모양(테두리 없음·배경만 등)으로. 버튼 이름은 누른 결과와 같아야 한다(예: "구독 관리"를 누르면 관리 화면, 해지 화면이면 "해지하기").
- **진행 표시는 사실이어야 한다** *(v0.3-F)*: "n/N" 단계 수는 실제 남은 화면 수와 같아야 한다. 확인·동의 화면도 단계에 포함한다. 현재 위치(내비게이션 활성 표시·aria-current)는 실제 화면과 일치해야 한다.
- **우선 화면**: 모바일 우선. 390px에서 먼저 설계하고 1440px로 확장. 두 폭에서 핵심 정보량은 같아야 한다(말줄임으로 핵심 정보 손실 금지).
- **접근성**: WCAG 2.2 AA. 텍스트 대비 4.5:1(큰 글자 3:1), 키보드 조작·포커스 표시, 터치 영역 최소 24×24px(권장 44×44px), 모션 감소 설정 존중.
- **스크롤 연출 범위** *(v0.2)*: 고정(pinning)·스크롤 연동 애니메이션 같은 스토리텔링 연출은 마케팅·랜딩 페이지에만. 웹앱의 과업 화면에는 쓰지 않는다. 쓸 때는 prefers-reduced-motion 대체(정지 화면)를 반드시 제공한다.

## 4. 라이팅 규칙 *(v0.2, 토스 Writing Principles + Apple HIG Writing)*
1. **목소리는 고정, 톤은 상황별** — 성공은 가볍게, 오류·위험·사고는 직설적으로.
2. **용어 목록 유지** — 같은 대상은 같은 단어로. 제품별 용어집을 산출물에 포함.
3. **버튼은 행동으로** — "결제하기", "보내기"처럼 무엇이 일어나는지 말한다. 재치 있는 라벨("가보자고!")보다 명확함.
4. **흐름 라벨 통일** — 시작 "시작하기" → 진행 "다음"(또는 "계속" 중 하나로 통일) → 끝 "완료".
5. **"우리"를 주어로 쓰지 않는다** — "저희가 불러오지 못했어요" 대신 "내용을 불러올 수 없어요". 소유격(내/나의)도 꼭 필요할 때만.
6. **오류는 문제 옆에, 고치는 방법으로** — 탓하지 않고 방법을 말한다. "비밀번호가 짧아요" → "8자 이상 입력해 주세요". "앗!", "이런!" 같은 감탄사 금지. 많은 사람이 겪는 오류는 문구가 아니라 흐름을 다시 설계.
7. **빈 화면엔 다음 행동** — 무엇을 할 수 있는지 + 그 행동 버튼. 빈 상태에만 중요한 정보를 두지 않는다.
8. **링크는 목적지를 말한다** — "여기를 클릭" 금지. "환불 규정 보기"처럼.
9. **입력 필드** — 라벨 + 예시 힌트(예: name@example.com). 금지 대신 방법("글자만 입력해 주세요").
   - *(v0.5-M)* **입력창 안내 문구(placeholder)는 잘려 보이지 않게 한다.** 폭이 좁으면 예시를 빼고 핵심 문구만 보인다(예: "검색어를 입력해 주세요 (예: 인공지능, 전기차)" → "검색어를 입력해 주세요"). 화면 폭 기준보다 **실제 입력칸 폭에 문구가 들어가는지 재서** 고른다. 짧은 문구도 안 들어가면 한 단계 더 줄인다(예: "검색"). **가장 짧은 단계는 가장 좁은 폭(320px)에서도 들어가야 한다.** 같은 역할의 입력창(홈 검색창·머리글 검색창)은 같은 문구 단계를 쓴다. 안내 문구는 라벨을 대신하지 않는다(접근성 이름은 따로).
10. **설정 설명** — 켰을 때 무엇이 되는지만 쓴다. 다른 설정으로 보낼 땐 위치를 말로 설명하지 말고 바로 가는 링크.
11. **과업 화면의 첫 줄은 정보** *(v0.3-D)* — 사용자가 확인하러 온 값(금액·상태·다음 행동)이 화면에서 가장 먼저, 가장 크게. 슬로건·감성 문구는 그 아래에 두거나 뺀다.
    - *(v0.5-I)* **입력이 과업인 첫 화면(검색, 로그인, 주소·번호 입력 등)은 그 입력창이 첫 줄이다.** 머리글(로고·메뉴) 다음에 바로 입력창이 오고, 그 위에 슬로건·서비스 소개·환영 문구를 두지 않는다. 브랜드 소개가 필요하면 입력창과 주요 내용 아래, 또는 빈 상태·첫 사용 순간에 둔다.
    - 이 철학 문서와 설계 규칙의 문장("판단은 줄이고…" 등)은 **만드는 사람의 기준이지 화면 문구가 아니다.** 화면에 옮겨 쓰지 않는다.
12. **장식용 외국어·영문 머리말 금지** *(v0.3-D)* — "YOUR MONTH, AT A GLANCE" 같은 영문 eyebrow는 정보가 없고 해요체 원칙과 어긋난다. 브랜드·마케팅 페이지에서만 예외. 같은 정보를 두 번 표시하지 않는다(예: "01 — 서비스 선택" + "1/3").
13. **의미 없거나 헷갈리는 문구·기호를 쓰지 않는다** *(v0.5-L)* — 아이콘·기호·단어는 뜻과 맞아야 한다. 돈과 무관한 곳의 `$`·`₩`, 의미 없는 장식 기호(✦·★ 남발), 내용과 다른 아이콘, 근거 없는 수치("판단 피로 70% 감소"), 무엇을 하는지 알 수 없는 라벨("스마트 탐색")은 쓰지 않는다. 확신이 없으면 아이콘 없이 글자로만 쓴다.

## 5. 검증과의 연결
- 검증 후보는 collab/notes/04-validation-candidates.md(V01~V17)를 따른다.
- **수치 임계값(예: 주요 행동 1개, 텍스트 스타일 8개 이하)은 아직 합격 조건이 아니다.** 지금은 측정값과 리뷰 의견으로만 기록한다.
- 번역 모드 화면은 V09(위험·비용 보존), V16(설명 방식) 수동 검토가 필수.
- v0.2 추가 검증 후보(04에 추가 요청 예정):
  - 되돌리기: 기본 모드의 주요 행동마다 취소/실행 취소 경로가 있는가, 안내 흐름에 건너뛰기가 있는가
  - 효과보다 읽힘: 반투명·블러·그라데이션 위 텍스트의 기본 상태 대비
  - 라이팅: 흐름 라벨 일관성, "우리" 주어·감탄사·"여기를 클릭" 탐지(보조 + 수동)
  - 스크롤 연출: 과업 화면에서 스크롤 연동 애니메이션 사용 여부, reduced-motion 대체 존재
