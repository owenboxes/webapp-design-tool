# 디자인 체크리스트

구현 중 자기 점검과 구현 후 수동 리뷰에 쓴다. 근거는 `philosophy.md`의 해당 절.
표시: **[확정]** 위반이면 실패 · **[측정]** 수치 미확정이라 값과 의견만 기록 · **[후보]** 리뷰에서 나왔지만 철학에 아직 없는 규칙(리뷰 의견으로만, 현재 없음) · 표시 없음은 리뷰 의견 · 괄호 안은 `verification.md`의 검사 ID.

## 1. 모드와 구조 (철학 §1)
- [ ] 모든 화면에 모드(기본/번역)가 정해져 있고 설계 문서에 적혀 있다 [확정]
- [ ] 기본 모드 화면은 결정 1개다. 주요 행동 수를 센다 [측정] (V01)
- [ ] 번역 모드 화면: 쉬운 요약 → 핵심 조건(금액·기간·위험·취소 방법)이 **항상 보임** → 용어 풀이 → 원문(접기 가능) → 행동 [확정] (V09, V16)
- [ ] 번역 모드 조건 문구가 사용자 상태에 따라 계산되고, 상태별 문구 표가 있다 [확정]
- [ ] 위험을 친근한 말로 축소하지 않았다 (예: 미수거래 → "외상") [확정]
- [ ] 기간 안에 취소할 수 있는 행동은 실행 후 "○○ 예정"으로 남고, 취소 경로가 있다 [확정] (V27)
- [ ] 예정 항목이 목록에서도 구분되고 취소 기한(이용 중이면 이용 종료일도)이 보인다 [확정 v0.4-H] (V27)
- [ ] 진짜 되돌릴 수 없는 행동은 실행 전 확인 + "되돌릴 수 없음" 명시 [확정]
- [ ] 위험이 작은 되돌릴 수 없는 행동(검색 기록·알림 목록 비우기 등)은 "(복구 불가)" 같은 짧은 표기 하나로 — 표기 누락은 실패, 과한 설명·팝업은 리뷰 의견 [확정 v0.5-K]

## 2. 위계와 첫 줄 (철학 §4-11·12, §3)
- [ ] 화면 첫 줄·가장 큰 글자가 사용자가 확인하러 온 값이다 (금액·상태·다음 행동)
- [ ] 영문 장식 머리말, 같은 정보 중복 표시(예: "01 — 서비스 선택" + "1/3")가 없다 [확정]
- [ ] 과업 화면의 슬로건·감성 문구가 첫 줄·화면 위쪽을 차지하지 않는다 [확정 v0.3-D]
- [ ] 입력이 과업인 첫 화면(검색·로그인 등): 머리글 다음 바로 입력창. 입력창 위에 슬로건·서비스 소개·환영 문구 없음 [확정 v0.5-I]
- [ ] 철학·설계 규칙 문장을 화면 문구로 옮기지 않았다 ("판단은 줄이고…" 등) [확정 v0.5-I]
- [ ] 섹션 부제·감성 소개·정보 없는 일러스트처럼 근거 없는 장식이 없다 (원칙 6, 리뷰 의견)
- [ ] 숫자·금액은 크고 굵게, 그룹은 여백으로 구분
- [ ] 글자 스타일은 역할 토큰으로, 수가 적다. 개수를 센다 [측정] (V12)
- [ ] 색은 역할 토큰으로만 쓴다. 컴포넌트의 원시 색 값 후보를 찾는다 [측정] (V13)

## 3. 행동과 되돌리기 (철학 원칙 8, §3)
- [ ] 단계 화면 하단 행동 ≤ 2 (주요 1 + 보조 1) [확정] (V25)
- [ ] 여러 단계 흐름: 상단 "← 이전"(선택 유지) + 흐름 닫기 하나 [확정] (V18)
- [ ] 선택지마다 "선택 취소" 없음, "건너뛰기"는 온보딩·선택 사항 안내에만 [확정]
- [ ] 버튼 이름 = 누른 결과. 목록 버튼의 접근성 이름에 대상이 들어간다 (예: "소리숲 해지하기") [확정] (V02)
- [ ] 흐름 라벨 통일: 시작하기 → 다음 → 마지막은 결과 라벨("동의하고 결제하기") [확정]
- [ ] 진행 표시 N = 확인·동의 포함 실제 화면 수, 내비 활성·`aria-current` 일치 [확정] (V26)

## 4. 누를 수 있어 보이는 모양 (철학 §3-E)
- [ ] 화살표(↗ › →)·밑줄·알약 테두리·손가락 커서가 비대화형 요소에 없다 [확정]
- [ ] 정보 태그는 버튼과 다른 모양(테두리 없음·배경만) [확정]

## 5. 상태와 기다림 (철학 원칙 5, §4-6·7)
- [ ] 주요 화면마다 로딩·오류·빈 상태가 있다 [확정] (V06)
- [ ] 로딩 중 눈에 띄는 주요 버튼이 없다. 탈출구는 보조 텍스트 버튼 하나 [확정 v0.4-G] (V06)
- [ ] 오류: 문제 옆에, 탓하지 않고 고치는 방법으로, 감탄사 없이. 데이터가 안전한지 말한다("구독 정보는 그대로예요")
- [ ] 빈 상태: 할 수 있는 일 + 그 행동 버튼
- [ ] 되돌릴 수 없는 작업은 "처리 중"과 "완료"를 구분한다
- [ ] 완료 알림이 콘텐츠를 가리지 않고, 방금 바뀐 항목이 목록에서 구분된다
- [ ] 알림 배너 톤이 내용과 맞다 (성공을 경고처럼 보이게 하지 않는다) [측정]

## 6. 라이팅 (철학 §4)
- [ ] 설계 문서에 정한 어조(기본 해요체)로 **모든 화면 문구가 통일**돼 있다. 확인 질문·빈 상태·오류·부제까지 전수 확인하고, 리뷰에 섞인 문구 예시를 적는다. 법적 원문·고유명사는 그대로 [확정 v0.5-J] (V07)
- [ ] "우리/저희" 주어, "앗!/이런!", "여기를 클릭" 없음 (V20)
- [ ] 소유격("내/나의")은 꼭 필요할 때만
- [ ] 링크는 목적지를 말한다 ("환불 규정 보기")
- [ ] 다른 화면·설정으로 보낼 때 위치를 말로 설명하지 않고 바로 가는 링크·버튼을 준다. 설정 설명은 켰을 때 무엇이 되는지만
- [ ] 입력 필드: 라벨 + 예시 힌트, 금지 대신 방법
- [ ] 입력창 안내 문구가 320·390·768·1440 모두 잘리지 않는다(빈 상태에서 측정, 머리글·팝업 안 입력창 포함). 좁으면 짧은 단계로 바뀌고, 가장 짧은 단계는 320에서도 들어간다. 같은 역할의 입력창은 같은 문구 단계. 접근성 이름은 안내 문구와 별도 [확정 v0.5-M]
- [ ] 용어집과 화면의 단어가 일치한다
- [ ] 기호·아이콘·단어가 뜻과 맞는다. 돈과 무관한 `$`·`₩`, 의미 없는 장식 기호, 내용과 다른 아이콘, 근거 없는 수치, 무엇을 하는지 알 수 없는 라벨이 없다 [확정 v0.5-L]

## 7. 반응형·접근성 (철학 §3)
- [ ] 390px에서 먼저 설계, 1440px에서 핵심 정보량이 같다. 말줄임으로 핵심 정보 손실 없음 [확정] (V08)
- [ ] 텍스트 대비 4.5:1(큰 글자 3:1), 효과·이미지 위 텍스트 포함, 접근성 설정을 켜지 않은 기본 상태 기준 [확정] (V14, V19)
- [ ] 유리·블러 효과는 내비게이션 레이어(상단바·탭바·시트 테두리)에만, 본문·목록·표 위에는 없다 [확정] (V19)
- [ ] 키보드로 전 흐름 조작, 포커스 보임, 본문 건너뛰기 링크 [확정] (V15)
- [ ] 묶음 입력(둥근 검색창처럼 틀 안에 입력·버튼이 있는 것): 포커스 때 **바깥 틀 하나만** 강조되고, 안쪽 입력칸의 사각 테두리·기본 outline이 따로 보이지 않는다. 포커스 표시 자체는 없애지 않는다 (visual-system §4) [확정]
- [ ] 대화상자·시트가 열리면 포커스가 안으로 들어가고 밖(뒤 화면·건너뛰기 링크)으로 나가지 않으며, Esc·닫기로 닫으면 연 버튼으로 돌아간다 [확정] (V15)
- [ ] 터치 영역 24×24px 미만 없음 [확정] (V23) — 44×44px는 권장(미달이어도 실패 아님). WCAG 2.5.8 예외(문장 속 링크, 주변 간격이 충분한 작은 대상)는 실패로 보지 않고 예외 사유를 기록. 숨긴 입력은 실제로 누르는 라벨 영역으로 잰다
- [ ] prefers-reduced-motion 존중, 과업 화면에 스크롤 연동 연출 없음 [확정] (V21)

## 8. 데이터·권한 요청 (철학 원칙 2)
- [ ] 개인정보·권한을 요청하는 곳마다 무엇을 왜 쓰는지 요청 가까이에 밝힌다 (V05)

## 9. 맥락과 근거 (철학 원칙 4·6·9·10)
- [ ] 사용 맥락이 적혀 있고, 조사인지 가정인지 구분했다 (V10)
- [ ] 홈 우선순위 근거(데이터 또는 가정)가 적혀 있다 (V17)
- [ ] 새 요소·새 패턴은 근거가 있다. 익숙한 관례를 먼저 썼다
- [ ] 감정 1개가 완료·위로 순간에 담기되, 과업을 늦추는 장식이 없다

## 10. 시각 체계 (visual-system.md)
- [ ] 색·분위기를 물었거나, 입력에서 추론한 색상 코드와 대비 표가 설계 문서에 있다 (리뷰)
- [ ] 강조색은 1개이고 주요 행동·선택 상태·포커스에만 쓴다 [측정]
- [ ] 글자 크기가 단계 안에 있다: 모바일·PC 단계를 합친 11·12·13·14·15·16·18·20·22·26·28·32px(±0.5) 밖의 값, 11px 미만 글자가 없다 [확정 V28 — `measurePage(page, {enforceScale:true})`]. 화면 폭별 단계(모바일 표·PC 표)를 지켰는지는 기록 [측정]. 11px는 시간·출처·배지 같은 보조 정보에만(2026-11-11 OWEN)
- [ ] 간격이 4px 단계(4·8·12·16·20·24·32·40·48·56·64·80) 안에 있다. 단계 밖 값 수를 기록 [측정 V28] (6·10·14px 같은 작은 안쪽 여백이 흔해 아직 강제하지 않음)
- [ ] 입력칸·체크박스 경계 대비 3:1 [확정] (WCAG 1.4.11, V14 확장)
- [ ] 과업 화면 전환 300ms 이하, reduced-motion에서 이동 없음 [측정] (V21)
- [ ] 글자를 그림 위에 바로 올리지 않았다. 올렸다면 대비를 쟀다 [확정] (V14)
- [ ] 실제 서비스의 고유 색·로고·글꼴·그림을 그대로 쓰지 않았다 (리뷰)

## 심각도 표기 (리뷰 결과)
- 🔴 반드시 고침: [확정] 위반, 틀린 정보, 사용자가 손해를 볼 수 있는 문제
- 🟠 권장: 철학과 어긋나지만 정보 손실은 없음
- 🟡 선택: 톤·여백 등 취향이 갈릴 수 있는 개선
